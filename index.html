Ocient blog · 2026-09-01

Inside OcientAIQ™: Modeling array queries

OcientAIQ now includes models to predict query costs for array overlap and containment operations, even before execution.

  • The core capability models the cost of queries that check for overlap between array columns in a table and elements within another array (either literals or from a subquery).
  • Six models are presented, categorized by whether the matching values are literals within the query or sourced from a second table, and whether the query returns only keys, keys plus matched attributes, or rows containing all values.
  • Key variables driving the models include N (number of rows), A (array element count), L (number of values to match), M (number of matching rows), and F (number of foundation nodes). Formulas are provided to estimate query time (T) based on these variables.
  • The models demonstrate that matching against values read from a table (versus literals) incurs a parsing cost, but can be more efficient for large value sets, and that selectivity impacts performance more significantly when payload is returned versus just keys.

Detecting low-and-slow beaconing with SQL over multi-year flow history

Ocient enables detection of low-and-slow command-and-control beaconing by leveraging long-term flow data analysis with SQL.

  • The detection method focuses on identifying consistent source/destination pairings, low byte counts, and regular intervals in network flow data over extended periods, even when traffic appears benign due to use of legitimate cloud services.
  • The core query groups flow records by source/destination IP, calculates the average and standard deviation of time gaps between connections, and flags pairs with regular intervals (gap_stddev < 0.1
  • avg_gap) and a sufficient number of contacts (contacts >= 20).
  • Performance relies on full-resolution (unsampled) flow capture combined with TimeKey® indexing, which builds multiple indexes across table columns at load time, enabling fast interactive queries over multi-year data sets.
  • OcientAIQ™’s architecture is designed for independent scaling of ingest, storage, and query concurrency, allowing efficient analysis of petabyte-to-exabyte scale data without performance bottlenecks or excessive costs.

What petabyte scale actually unlocks

  • OcientAIQ™ Unified Data Platform is designed to solve the traditional trade-off between data retention, cost, and query performance by scaling ingest rate, storage depth, and query concurrency independently.
  • The platform uses TimeKey® indexing to build multiple indexes across table columns at load time, enabling faster interactive queries by selecting the optimal access path for each query rather than relying on a single clustering key.
  • OcientAIQ supports sustained ingest rates of hundreds of millions of events per hour and is designed for use cases requiring full-resolution data and long retention periods (years of history) – examples include space situational awareness, anomaly detection, and real-time ad tech matching.
  • Pricing is based on fixed deployment capacity instead of per-query or data-scanned costs, encouraging continuous analysis and accommodating AI agents, and the platform can be deployed on-premises or in a private cloud to address data sovereignty and security concerns.

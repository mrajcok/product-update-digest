Cribl Search adds OCSF mapping for more consistent searches | Cribl

Cribl Search now supports mapping fields to the Open Cybersecurity Schema Framework (OCSF) v1.8 for more consistent searching across disparate security data sources.

  • The feature, implemented via dataset rules (GDI Step 3) in Cribl Search’s Lakehouse Engine, standardizes field names based on OCSF definitions.
  • Users can choose to add OCSF mapped fields alongside original fields or replace the original fields, allowing flexibility in data presentation.
  • Mappings are associated with datatypes to ensure appropriate field relationships are applied during event matching.
  • Custom datatypes can be created or built-in types cloned to enable users to extend and tailor schema mappings beyond the initial OCSF v1.8 implementation.

Ocient blog · 2026-10-14

Retrospective IOC sweeps: Establishing whether you were ever exposed

Ocient introduces retrospective IOC sweeps enabling organizations to determine if they were previously compromised by newly discovered threat indicators.

  • OcientAIQ™ allows users to perform retrospective threat hunts by joining newly received threat intelligence indicators with years of historical, full-resolution flow and DNS data.
  • The solution utilizes ANSI SQL queries, specifically indexed joins on fields like destination IP address and timestamps, to quickly identify past exposures without requiring data rehydration or costly scans.
  • The system supports automated, standing jobs that run sweeps against all new intelligence batches, surfacing matches as alerts within existing SIEM/SOAR tools.
  • Ocient’s architecture keeps all historical data indexed and queryable in a single tier, avoiding the performance limitations and costs associated with tiered storage and federated search common in other security platforms.

Ocient release notes

OcientAIQ Unified Data Platform Release Notes — 28.0

  • Ocient has released the Ocient Management UI, a web-based interface for system health monitoring, query activity, data ingestion, storage, node status, an interactive SQL Console, and a Pipeline Builder.
  • Data Pipeline loading now includes accurate metrics for ingest, fan-out, and filtering; pipelines can be quiesced with QUIESCE, and restarted at a specific file offset with ALTER PIPELINE.
  • The Ocient MCP Server (ocientmcp Python package) is now available, enabling AI agents and code editors to interact with Ocient systems via the Model Context Protocol (MCP).
  • Data Flows have been added, allowing sequential execution of multiple SQL statements with support for variables, loops, conditional branching, and error handling.
  • New SQL syntax features include FETCH FIRST/FETCH NEXT, the ROW() constructor (alias for tuple()), hexadecimal/octal/binary integer literals, underscore digit separators, and WITH RECURSIVE for recursive CTEs.
  • Data Pipeline metrics have been enhanced to show throughput details (including fan-out) with new views for rows and bytes processed; ALTER PIPELINE SQL is enhanced to update pipeline configurations in place.
  • Kerberos authentication is now supported for loading data from HDFS sources, along with Parquet data loading from HDFS.
  • New array functions have been added: ARRAY_INTERSECT_DISTINCT_COUNT, ARRAY_TRANSFORM_WITH_ORD, JACCARD_SIMILARITY, and ZIP_WITH_ORD.
  • Workload management now includes GRANT and REVOKE support for USE and VIEW privileges on service classes.
  • Machine learning model updates include the UNDERSAMPLING model, expanded training metrics (accuracy, confusion matrix, R², RMSE, etc.), the ROOT_MEAN_SQUARED_ERROR aggregate function, standardized model options, and new predict and predict_probabilities meta functions.
  • DDL statements have been extended with ALTER TABLE SET COMMENT, GET NODE TOKEN/REVOKE NODE TOKEN, and new parameters for CREATE/ALTER CONNECTIVITY_POOL (related to SSO and OpenAPI settings).
  • New scalar functions MAP_PUT, MAP_GET, and MAP_DELETE provide map functionality within SQL.
  • The HTTP Query API now correctly terminates queries exceeding service class limits, resolving a previous indefinite FINALIZING state issue.
  • Several new system catalog tables (sys.mcp_tools, sys.pipeline_metrics_current, sys.pipeline_metrics_historical) and column additions have been implemented for improved monitoring and reporting.
  • Data Pipelines are now the preferred method for loading data; the LAT functionality is deprecated and will be removed in a future release.
